## 1. TCP/IP 分层与一次 HTTP 请求的全路径

读完应该能回答：

- 应用层、传输层、网络层、数据链路层各自管什么？
- 一次 `curl https://example.com/`，从敲下回车到看见响应，**按顺序**发生了哪些事？

关键概念清单：

- OSI 七层 vs TCP/IP 四层（实际工程语境）
- DNS 查询：递归 vs 迭代、A/AAAA/CNAME、`/etc/hosts` 与 `/etc/resolv.conf` 的优先级
- ARP：在二层把 IP → MAC 解析出来；何时触发、缓存在哪
- 路由查表：`ip route` 的本机视角，默认网关的含义
- TCP 三次握手 / 四次挥手；半连接队列、全连接队列
- TLS 握手（在 TCP 之上叠的一层）
- HTTP/1.1、HTTP/2、HTTP/3（QUIC over UDP）的语义差异

::: tip 学习目标产物
一张「一次 HTTPS 请求时序图」，覆盖：DNS → ARP → TCP → TLS → HTTP，标注每一步在 OSI 哪一层。

## 2. Linux 内核网络栈：从网卡到应用

读完应该能回答：

- 数据包进入网卡后，**到底走哪一条路**才能落到一个 socket 上？
- 一个出站数据包，**从用户态 `write()` 到网线**的路径是怎样？
- netfilter 的 5 个 hook 点，分别在内核栈的哪个位置？

关键概念清单：

- 数据包三种走向：
  - 入站 → 给本机进程（PREROUTING → 路由判定 → **INPUT** → 本机协议栈）
  - 入站 → 需要转发（PREROUTING → 路由判定 → **FORWARD** → POSTROUTING）
  - 本机出站（本机协议栈 → **OUTPUT** → 路由判定 → POSTROUTING）
- 五条链：`PREROUTING / INPUT / FORWARD / OUTPUT / POSTROUTING`
- 五张表：`filter / nat / mangle / raw / security`
- 「表 × 链 × hook」对应矩阵（哪个表在哪些链上有钩子）
- conntrack（连接跟踪）：状态机 `NEW / ESTABLISHED / RELATED / INVALID`
- 路由判定（routing decision）发生在哪两个点

## 3. iptables 规则书

读完应该能回答：

- 一条 `iptables -A INPUT -p tcp --dport 22 -j ACCEPT` 命令每个段是什么含义？
- 规则在一条链里**怎么排序、怎么短路**？
- 为什么大家都写 `-m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT` 作为第一条？

关键概念清单：

- 语法骨架：`-t <表> -A/-I/-D <链> <匹配条件> -j <目标>`
- 跳转目标：`ACCEPT / DROP / REJECT / RETURN / LOG / 自定义链`
- 匹配模块（`-m`）：`conntrack / multiport / mark / addrtype / iprange / limit / state`
- 命中即终止 vs 命中后继续（如 `LOG` 后继续匹配）
- `iptables-save` / `iptables-restore` 与持久化（distro 间差异）
- 与 firewalld 的关系：firewalld 是 iptables/nftables 之上的策略管理器，**两者直接混用容易自相矛盾**

## 4. NAT 深入：SNAT / DNAT / MASQUERADE

读完应该能回答：

- 「私网出公网」「公网访问私网服务」分别用哪种 NAT？规则写在哪个表的哪条链上？
- NAT 规则只在「连接的第一个包」生效，那同一连接的后续包怎么自动改地址？
- 为什么 `MASQUERADE` 写在 POSTROUTING 而不是 PREROUTING？

关键概念清单：

- SNAT：改源地址，POSTROUTING
- DNAT：改目的地址，PREROUTING（或 OUTPUT，本机自访问时）
- MASQUERADE：动态 SNAT，出口 IP 不固定时用
- NAT 表的 **conntrack 联动**：首包决策、后续包查 conntrack 自动改写
- Hairpin / NAT loopback：本机访问自己映射端口的特殊情况（就是你刚踩的坑的近亲）
- 端口转发的两种实现：**iptables DNAT** vs **userland docker-proxy**

## 5. Docker 网络模型

读完应该能回答：

- 默认 bridge 模式下，容器从 `eth0` 发的包到外网的完整路径是什么？
- `docker network create` 自定义网络比默认 bridge 多了什么？为什么强烈推荐用？
- `-p 8080:80` 在内核里到底注入了哪几条 iptables 规则？

关键概念清单：

- 五种网络模式：`bridge / host / overlay / macvlan / none` 各自的适用场景
- 默认 bridge：`docker0` + 每个容器一对 `veth` + 自动注入 iptables 规则
- Docker 在 iptables 创建的链：`DOCKER` / `DOCKER-USER` / `DOCKER-ISOLATION-STAGE-1/2`
- 自定义 network：内置 DNS（容器名解析）+ 容器间不需要走宿主机端口映射
- `-p` 的两条核心规则：
  - `nat` 表 `DOCKER` 链：`DNAT --to 容器IP:容器端口`
  - `filter` 表 `DOCKER` 链：`ACCEPT` 转发到目标容器
- userland docker-proxy 进程的作用与争议（性能、为什么 hairpin 还能通）

## 6. 抓包与排错工具

读完应该能回答：

- 「Ping 通端口不通」「连接被拒绝」「超时」「No route to host」分别意味着卡在哪？应该用哪个工具下手？
- 怎么在容器里抓只属于这个容器的包？

工具清单：

| 工具         | 一句话用途                          | 一个最常用的命令                                 |
| ------------ | ----------------------------------- | ------------------------------------------------ |
| `ping`       | ICMP，确认三层可达                  | `ping -c 4 <ip>`                                 |
| `traceroute` | 沿途跳数                            | `traceroute <ip>`                                |
| `ss`         | 替代 `netstat`，看监听与连接        | `ss -tlnp` / `ss -tnp state established`         |
| `tcpdump`    | 抓包                                | `tcpdump -i any -nn 'tcp port 1983' -w out.pcap` |
| `conntrack`  | 看连接跟踪表                        | `conntrack -L`                                   |
| `iptables`   | 查规则与计数                        | `iptables -L -n -v --line-numbers`               |
| `nsenter`    | 进入指定进程/容器的命名空间执行命令 | `nsenter -t <pid> -n tcpdump -i eth0`            |
| `ip`         | 看网卡、路由、邻居                  | `ip a` / `ip r` / `ip neigh`                     |

::: tip 学习目标产物
一张「症状 → 优先工具」对照表，例如：

- `No route to host` → 先看 `ip route` 与 `iptables -L INPUT`
- `Connection refused` → `ss -tlnp` 看进程是否在监听
- 三次握手卡住 → `tcpdump` 抓 SYN/ACK 序列
  :::
